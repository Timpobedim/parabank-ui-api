# PB-010. Кириллица из браузерной формы регистрации сохраняется HTML-сущностями

| Поле | Значение |
|---|---|
| Серьёзность | Major — порча данных у любого пользователя с нелатинским именем |
| Приоритет | High (для русскоязычной аудитории) |
| Окружение | parasoft/parabank (digest `sha256:747453a0…`), Chromium 151 (Playwright 1.62) · 11.09.2026 |
| Воспроизводимость | стабильно |
| Автотест | `tests/ui/test_encoding_ui.py::test_cyrillic_name_entered_in_browser_is_saved_as_text` (xfail) |

## Шаги

1. Открыть **Register** в браузере, в поле **First Name** ввести «Ян», остальные поля — латиницей.
2. Нажать **Register**, затем `GET /services/bank/login/<логин>/<пароль>`.

## Ожидаемый результат

`"firstName": "Ян"`.

## Фактический результат

`"firstName": "&#1071;&#1085;"`, и так же в приветствии личного кабинета.

## Анализ

Страницы отдаются как `text/html;charset=ISO-8859-1`. Символы вне этой кодировки браузер
отправляет из формы числовыми HTML-сущностями, а сервер сохраняет их как текст. Каждая буква
превращается в 7 символов, поэтому имя длиннее 4 букв или кириллический город упираются
в ограничение длины поля — и регистрация срывается с ложной ошибкой (см. PB-011).
Через HTTP-форму в UTF-8 кириллица сохраняется корректно — так тесты и готовят данные.
