# ParaBank UI + API Tests — автотесты демо-банка

UI- и API-автотесты демонстрационного интернет-банка ParaBank: регистрация и вход, счета,
переводы, оплата счетов, кредиты, профиль. Проверки идут на двух уровнях — REST API и интерфейс, —
а в сценариях e2e данные готовятся через API и проверяются в интерфейсе, и наоборот.
13 найденных дефектов оформлены баг-репортами и закреплены тестами-«сторожами».

**Стек:** Python 3.12 · Playwright · pytest · requests · Allure · Pydantic v2 · pydantic-settings ·
Faker · Docker · GitHub Actions · ruff · mypy (strict).

## Найденные дефекты

Тест каждого дефекта проверяет **ожидаемое** поведение и помечен `known_defect`; хук в `conftest.py`
превращает пометку в `xfail(strict=True, raises=AssertionError)` и добавляет в Allure ссылку
на баг-репорт. Пока дефект есть, прогон зелёный; исправят — тест станет XPASS и прогон покраснеет.

## Почему набор идёт последовательно

Первая версия запускалась в 4 потока (pytest-xdist) и случайно падала на подготовке данных:
регистрация клиента то проходила, то возвращала «логин занят». Разбор показал, что дело не в тестах:
из 8 одновременных регистраций ParaBank теряет 4–5, из 24 одновременных открытий счёта — 12 (PB-013).
Сериализовать в тестах каждую запись значило бы спрятать дефект, поэтому набор идёт последовательно
(около 35 с), а сам дефект закреплён двумя тестами, которые создают параллельную нагрузку намеренно.

## Запуск

```bash
docker compose up -d                   # свой экземпляр ParaBank: http://localhost:8090/parabank
uv sync --group dev
uv run playwright install chromium
uv run pytest                          # весь набор; фикстура дождётся, пока стенд поднимется
uv run pytest -m "api and not known_defect"   # только API без тестов-«сторожей»
allure serve allure-results            # отчёт (нужен Allure CLI)
PARABANK_BASE_URL=https://parabank.parasoft.com/parabank uv run pytest -m sanity   # публичный стенд
```

## Структура

```
src/parabank/
├── api/          # client.py — REST-клиент, models.py — Pydantic-модели, registration.py — клиент через HTTP-форму
├── pages/        # Page Object: вход и регистрация, обзор, счета и переводы, оплата, профиль
├── data/         # фабрики на Faker и найденные лимиты длины полей
└── config.py     # адрес стенда и таймауты из переменных окружения
tests/
├── api/          # клиенты, счета, операции, дефекты API
├── ui/           # регистрация, вход, счета, оплата, кириллица и длина полей
└── e2e/          # API + UI в одном сценарии
docs/bug-reports/ # PB-001 … PB-013
```
